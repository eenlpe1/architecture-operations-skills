# Issue tracker: Local Markdown

Harness development tasks live in `.scratch/<feature>/`. Keep the spec in `spec.md` and one numbered task per file in `issues/NN-slug.md`. Record triage state as a `Status:` line using [triage labels](triage-labels.md); append discussion under `## Comments`.

When an engineering skill says to publish or fetch a task, use these local files. Public issue/PR work requires the user's request. PRs are not an automatic request surface.

The current contribution has a separately authorized sanitized GitHub tracking issue; that does not move routine development or private incidents into GitHub. The repository contribution process requires an issue before substantial public contributions.

Private operational cases belong outside the repository, in the runtime user's private context directory. Never copy workplace identifiers, credentials, state, or incident evidence into development tasks intended for publication.
